## Finding disposition

| Finding | Resolution and proof |
| --- | --- |
| Medium: request-budget deferral after a received write returned to pending | Fixed. Only a pre-write deferral may return to pending. A post-receipt deferral retains sent_at, status/body hash/validated response and becomes uncertain; automation is blocked. Regression asserts no scheduler redispatch. Real file-backed worker plus duplicate/restart/reconciliation sends exactly one equipment write. [Worker proof](evidence/fnd-security-budget-worker.txt). |
| Low-medium: inherited-auth 401 invalidated the saved token | Fixed for the four explicitly inherited operations: faction detail and module read/install/remove. They report unresolved operation authorization without reclassifying the agent token. Every path still sends one agent bearer and never an account fallback. Four transport regressions verify error, preserved state and bearer. Authoritative agent-profile 401 retains its existing invalid-credential handling. |
| Low: non-string operation/command caused 500 | Fixed at the request boundary. Catalog selection uses only strings, while validation rejects the original invalid input with 422. Both array selectors have HTTP regressions. |
| Low, reasoned: Stop snapshot could replace a concurrent receipt | Fixed structurally. Conditional state updates and atomic JSON-path updates change only stop_requested_at; no merged outcome snapshot is written. No read transaction holds a SQLite snapshot across the write. Existing stale-read/receipt regression and real before/after-reservation workers pass. [Races](evidence/fnd-security-stop-workers.txt). |
| Informational: refine input wording / transfer cooldown | Wording now calls the 100-total-cargo-unit floor and transfer cooldowns client policies. Exact refinery input selection remains unknown; the preview does not promise that arbitrary cargo is a valid recipe. Jump drive/completed-gate restrictions are also labeled client policy. |
| Informational: additional destructive styling / last-ship guard | No new policy added. Scrap/jettison/supply use destructive approval styling. Contract acceptance/delivery and equipment/warp retain exact terms/effects and explicit approval. A last-ship or command-ship prohibition would prevent a valid official manual command; the adopted scope instead uses exact typed scrap actor, acknowledgement and permanent-loss warning. Last-ship removal and agent-only commands were exercised with fixtures. |
| Informational: accumulating manual read history | Deferred retention design. Each response has a 2 MiB transport bound and reads share the request budget, but observation history has no total-size retention cap. This remains a local disk-growth limit, not a claimed accepted property. No durable history was deleted to address it. |

All six targeted failing cases were reproduced before changes. The first implementation pass misplaced a named argument and was rejected by tests; that local error was corrected before publication. No failure was hidden or converted into a passing stage record.
